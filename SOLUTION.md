# Running this

Python 3.10+, standard library only. No install step.

```bash
python3 -m stackgen               # both answers, as one JSON object
python3 -m stackgen.issues        # the issues report
python3 -m unittest discover -s tests
python3 tools/check_inputs.py     # optional, checks the supplied files
```

The JavaScript prototype produces the same JSON:

```bash
cd stackgen/js && node solution.js
```

## Generated answers

| File | Contents |
|---|---|
| `answers/answers.json` | Question A and Question B for the manifest's `query_defaults` |
| `answers/issues.json` | The issues report |

Both are regenerated by the commands above.

## Layout

```
docs/spec.yaml            schema of the supplied files, written from EXTRACT_NOTES.md
stackgen/spec_models.py   generated from it
stackgen/loader.py        shared file access; both questions go through it
stackgen/question_a.py    Terraform management evidence
stackgen/question_b.py    application context and responsibility
stackgen/issues.py        issues report
stackgen/__main__.py      runs both questions
stackgen/js/              the prototype, same structure
tests/test_questions.py   17 tests
DESIGN.md                 design note
```

## Regenerating the models

```bash
python3 -m datamodel_code_generator \
  --input docs/spec.yaml --input-file-type openapi \
  --output-model-type dataclasses.dataclass \
  --target-python-version 3.10 \
  --use-schema-description --use-field-description \
  --output stackgen/spec_models.py
```

Only needed if `docs/spec.yaml` changes. `datamodel-code-generator` is a
development tool; the solution itself has no dependencies.
